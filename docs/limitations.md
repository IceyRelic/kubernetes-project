# 功能与可靠性边界

- 实训项目，时间/个人贡献来自材料和自述；2026年10月修复/测试有Codex辅助，尚需本人独立理解与复现。
- 机构Java应用仅补注册/登录/题目查询/未判题保存/本人历史等；不执行Python，不是真实隔离判题，执行时间/内存/分数不伪造。
- 单入口HAProxy/Keepalived没有已验双机切换；五节点Ready不是生产可用率证明。
- ES单节点yellow有未分配副本，NFS单点；普通rsync不是在线ES一致性备份。没有ES快照恢复/高吞吐/长期留存验收。
- Fluent Bit没有持久磁盘spool；持续重试仍有不可恢复错误、内存上限、采集器重启及源日志轮转的丢失边界。维护期已发生丢记录。
- 原采集策略排除kube-system；不称全系统日志完整采集。
- Scheduler/Controller无抓取目标、KSM ListErrors/HPA对象指标缺失仍待单独定位；HPA控制器已工作不证明其对象监控完整。
- 12规则48模拟断言不等同12种真实故障全部演练；同邮箱邮件故障告警不能保证自己送达。没有MTTD/MTTI指标。
- 当前MySQL/NFS备节点暂停，无实时复制/镜像；历史复制通过不能写成当前持续正常。
- MySQL实际异步TLS传输，原通道证书身份核验未开启；未验自动切换、长期复制延迟或实际重启。
- 原应用JDBC仍使用useSSL=false，模板保留原行为；MySQL复制TLS结论不能推广为所有数据库连接已加密。
- NFS --delete删除传播，未建立生产历史版本/ACL/xattr等全面保留政策。
- 原CentOS7/K8s1.18/Docker18.6等环境已旧，发布模板保留原API；未验证新版兼容或从零重建。
- 地址/镜像/Secret引用为发布转换，未部署本公共版本；没有复制institution业务代码或假称工件可直接下载。
